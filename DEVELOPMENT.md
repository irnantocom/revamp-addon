### Architecture Decisions

#### 1. Selector Generation
**Decision**: Priority-based selector generation
**Rationale**: 
- data-* attributes are most stable across deployments
- IDs can be auto-generated by frameworks (avoid react123, ember456)
- CSS paths work for structural stability
- XPath is fragile but always works

#### 2. Message Passing
**Decision**: All communication through background service worker
**Rationale**:
- Manifest V3 requirement
- Centralizes AI requests for Phase 2
- Better security model
- Easier to debug

#### 3. Visual Overlay
**Decision**: Direct DOM manipulation (not Shadow DOM yet)
**Rationale**:
- Simpler implementation for MVP
- Shadow DOM adds complexity
- Can be added in Phase 2 if needed

#### 4. Edit History
**Decision**: In-memory undo stack (max 50 operations)
**Rationale**:
- Simple and fast
- No persistence needed for MVP
- Sufficient for typical editing sessions

### Asset Downloader Strategy

1. Parse all `<img>`, `<video>`, `<link>`, `<style>` tags
2. Extract URLs (handle relative/absolute)
3. Fetch with appropriate CORS handling
4. Convert to base64 or save as files
5. Rewrite URLs to local paths

### CSS Extraction Plan

1. Collect all `<link rel="stylesheet">` URLs
2. Fetch external stylesheets
3. Collect inline `<style>` tags
4. Optionally: compute styles for selected elements
5. Bundle into single CSS file or keep modular

## Known Issues

**Problem**: Content script may not be loaded on some pages

**Fix for Phase 2**: Improve detection and auto-injection

### Issue #2: Cross-Origin Asset Access
**Problem**: Some assets may be blocked by CORS
**Workaround**: Fall back to original URLs
**Fix for Phase 2**: Implement proxy or base64 encoding

### Issue #3: SPA Route Changes
**Problem**: Selectors may break after route change
**Fix for Phase 2**: MutationObserver + re-resolution
